# Homepage / Match 切换性能优化与验证

日期：2026-08-31。范围：Cocos Creator 3.8.7 源码；未执行小游戏打包、手机测试或 Git 推送。

## 确认的开销

- 开始比赛原先串行经过 Match 场景加载、比赛弹窗/字体/数据加载、场上头像和圆框加载。桌面首次采样场景启动约 133ms，球场准备完约 593ms；这不是手机计时。
- 首页字体原先整树更新两遍。一次返回采样调用字体 setter 539 次，230 个标签确实换字体，其中 217 个位于隐藏页面；setter 总耗时约 126ms。
- 当前 Creator 引擎设置 Label.font 会立即重建文字渲染数据，包括隐藏标签。CPU 采样也观察到文字/纹理上传开销。
- 动态事件弹窗及胜负弹窗原先先挂到激活的场景，随后才隐藏，导致额外的激活工作。

## 改动

- 在备赛页准备 Match 场景和固定运行资源；按本场双方总评最高的五人预加载头像及圆框。只缓存资源，不缓存 Scene 实例、控制器或比赛状态。失败后可重试。
- 比赛开始后后台准备返回首页所需资源；返回按钮不再等待预加载 Promise。
- 首页预加载每次读取当前阵容，避免启动时空阵容被永久缓存，遗漏之后招募的球员；补上主页球场的圆框预加载。
- 首页字体每帧最多处理八个待更新标签，持续优先可见标签；不再整树更新两遍。场景销毁时停止任务。
- 胜负弹窗、事件弹窗先隐藏再挂到场景，避免不必要的激活。PlayerEventController 原有的事件入场/点击保护修改保持不变。
- 场景、预制体及比赛/预算/存档规则不在本次修改范围。

## 验证

1. `node --test tests/*.test.cjs`：65 项通过，其中 11 项新测试覆盖资源合并、失败重试、阵容变化、字体分帧、销毁取消和隐藏弹窗初始化。
2. Creator 预览已定向刷新修改脚本，确认运行代码包含预加载与分帧函数。
3. 多轮 Homepage → Match → Homepage 往返成功，包括返回备赛页。最终所有 Label 均有字体，事件弹窗隐藏、初始化完成、按钮绑定正常。
4. 提前准备后的首次 Match 就绪采样约 206ms；重复进入常见采样约 175–289ms。未充分预热或同时运行其他本地检查时也观察到约 421ms 的采样，不能用这些桌面数字承诺手机表现。
5. 返回首页仍有界面重建/纹理上传的帧峰值；此次优化未证明手机约三秒的停顿已完全消失。
6. TypeScript 全量检查仍有项目既有诊断；HomeUiController 中原有的 `richText.font = label.font` 类型错误也仍在。本次没有更改该行，不能称全项目编译干净。
7. 当前 Homepage/招募结果预制体另有未提交修改，预览持续报告 `[RecruitmentController] Missing recruitment UI references.`。保留这些资产修改，没有把此报错当作本次改动修复或验证通过。
