# 进球与防守篮板瞬间卡顿：修复与验证

日期：2026-08-31。修改限于 MatchController 的播报绘制，不更改比分、篮板归属、回合规划、球场动作时长或球权交接规则。

## 确认的瓶颈

进球和篮板动作均同步调用播报回调。旧逻辑每新增一条播报就改写全部五行 RichText；普通进球一条播报触发五次改写，篮板两条触发十次，三条连播触发十五次。Creator 的 RichText.string 会同步重新排版并生成文字片段，与进球/抢板动画共用主线程。

桌面预览实测旧回调约 5–16ms（部分为热缓存），不是手机的一秒实测。此前移除的回合空等只能修复逻辑等待，不能消除文字绘制造成的停顿。

## 本次修改

- 动画回调仅把播报加入队列，不调用富文本绘制。
- 每帧最多渲染一条新播报；复用五个现有的时间/内容节点，历史行只换父槽位，不再改写内容。
- 最新行背景、历史行背景保留在原槽位；保持原字体、字号、换行宽度和球员姓名颜色。
- 比赛播报启用 CHAR 字符缓存，复用已经绘制的字形，减少整段文字反复上传纹理。
- 队列最多五条，与原本可见的五条历史记录一致；比赛重开清除旧队列和旧文本，复用节点。
- 富文本组件在比赛初始化时创建，并在配置字体等属性期间暂时禁用，避免初始化中间态反复排版。

- 新增八项回归测试：进球、篮板、连播回调不绘制；每帧一行；历史复用；队列有界；重开清理；空闲帧不绘制；字体/颜色/宽度/缓存设置。
- `node --test tests/*.test.cjs`：73 项全部通过。
- TypeScript 全量检查仍有 275 条既有输出；本次 MatchController/MatchCourtSimulation 没有诊断。不能称全项目类型检查通过。
- Creator 预览已刷新源码，实际版本包含队列、五行复用和 CHAR 缓存。
- 第一轮仅复用/分帧版本：51 次出手全部完成，24∶27 与预定比分一致，球权无不匹配；仍观察到个别长渲染帧，因此继续加入字符缓存。
- 最终版本：59 次出手全部完成，29∶26 与预定比分一致。监测记录 52 次播报回调，其中 24 次进球、13 次未进且防守篮板；其余包括进攻篮板/罚球等。
